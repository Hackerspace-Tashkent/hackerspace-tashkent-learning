# HTTP API: свой сервер и клиент к нему

## Что такое API

Программа, к которой можно обратиться за данными, **не читая её код**.

Датчик воздуха пишет числа в файл. Приложение спрашивает «что сейчас» —
и получает JSON. Приложению не важно, откуда взялись числа: из файла,
из датчика, из базы. Это и есть API: договорённость «вот так спрашивай,
вот так отвечай».

## Анатомия запроса

Запрос — это метод, путь, заголовки и иногда тело.

| Метод | Что значит |
|---|---|
| `GET` | спросить, ничего не менять |
| `POST` | передать новое |
| `PUT` | заменить целиком |
| `DELETE` | удалить |

```bash
curl http://127.0.0.1:8000/readings
curl -X POST -H "Content-Type: application/json" \
     -d '{"pm25": 42.3}' http://127.0.0.1:8000/readings
```

## Код ответа — главное, что читает человек

| Код | Значит | Чей баг |
|---|---|---|
| `200` | всё хорошо | — |
| `201` | создано | — |
| `400` | запрос неправильный | клиент |
| `401` | нет прав | клиент |
| `404` | не найдено | клиент |
| `500` | сервер сломался | **сервер** |

**Правило, которое экономит часы: код 500 — это баг на сервере.** Чинить
клиент бессмысленно, пока сервер падает. Сначала вывод сервера, потом клиент.

## JSON

Обычный формат для таких ответов:

```json
{"time": "2026-10-01T12:00:00", "pm25": 42.3}
```

Есть числа, строки, `true`/`false`, массивы и вложенные объекты. Всё.

## Свой сервер без фреймворков

В Codespaces **нет ни flask, ни requests**, и это к лучшему: увидишь сам
протокол, а не привычки фреймворка. Всё нужное есть в стандартной
библиотеке.

Создай `lab-work/api.py`:

```python
#!/usr/bin/env python3
import json
import os
from http.server import BaseHTTPRequestHandler, HTTPServer

DATA_FILE = "data.json"


def load():
    try:
        with open(DATA_FILE, encoding="utf-8") as f:
            return json.load(f)
    except (OSError, ValueError):
        return []


class Handler(BaseHTTPRequestHandler):
    def reply(self, code, payload):
        body = json.dumps(payload, ensure_ascii=False).encode("utf-8")
        self.send_response(code)
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def do_GET(self):
        if self.path == "/health":
            return self.reply(200, {"ok": True})
        if self.path == "/readings":
            return self.reply(200, load())
        self.reply(404, {"error": "not found"})


HTTPServer(("127.0.0.1", 8000), Handler).serve_forever()
```

И файл с данными `lab-work/data.json`:

```json
[
  {"time": "2026-10-01T12:00:00", "pm25": 42.3},
  {"time": "2026-10-01T12:05:00", "pm25": 39.8}
]
```

Запусти и спроси сам себя:

```bash
cd lab-work
python3 api.py &
curl -s http://127.0.0.1:8000/health
curl -s http://127.0.0.1:8000/readings
curl -s -i http://127.0.0.1:8000/nope
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8000/nope
```

Остановить: `Ctrl+C`.

## Почему адрес `127.0.0.1`, а не `0.0.0.0`

`0.0.0.0` — это «слушай во всех интерфейсах», то есть сервер становится
виден другим машинам в сети. Для учебной задачи это лишнее и небезопасно.
`127.0.0.1` — только твоя машина. Наружу отдавай осознанно.

## Почему данные в файле, а не в коде

Чтобы **проверить сервер, не перезапуская его**. Поменял `data.json` —
ответ изменился сразу. Если всё зашито в коде, то каждый тест требует
перезапуска, и через пять минут ты перестанешь тестировать.

## Ключи: почему не в коде

**Ключ в клиентском коде — это опубликованный ключ.** Особенно на Pages:
там всё видно любому, кто откроет исходник страницы. Секреты живут
на сервере, а не в том, что скачает пользователь.

## Что делать, когда 500

1. Открой вывод сервера — правда там, а не в сообщении клиента.
2. Частая причина: невалидный JSON в теле запроса.
3. Вторая частая: путь, на который сервер не умеет отвечать, а клиент
   ждёт 200.

## Итог

Сервер — это программа, которая слушает порт и отвечает по HTTP.
`curl` — самый простой клиент, и его достаточно для проверки.
Ключевой навык — **читать код ответа**, а не угадывать.
