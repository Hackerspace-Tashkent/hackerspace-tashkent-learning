# Урок 6. GitHub Actions

## Что это такое

GitHub Actions — это компьютер, который запускает твой код за тебя. Ты
оставляешь в репозитории файл с описанием, что делать, а GitHub при каждом
push запускает это сам, без твоего компьютера.

```
ты пушишь код  →  GitHub замечает  →  запускает виртуальную машину
                →  выполняет команды →  показывает результат
```

Главная польза: **проверка не зависит от того, помнит ли человек её запустить.**
Кто-то запушил сломанный код — сразу упало. И упало у всех, одинаково.

## Где лежит файл

`.github/workflows/имя.yml` в корне репозитория. Имя — любое, расширение
`yml` или `yaml`. Всё, что лежит в `.github/workflows/`, GitHub считает
описанием автоматизации.

Это **обычный текст**, а не магия. Его можно открыть, прочитать, исправить
руками.

## Минимальный workflow

```yaml
name: Проверка

on:
  push:
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - name: Забрать код
        uses: actions/checkout@v4

      - name: Проверить практику
        run: ./labs/level-0/01-terminal/check.sh
```

Разберём по строкам.

**`name`** — как называется прогон в интерфейсе.

**`on:`** — когда запускать. `push` — при любом пуше, `pull_request` — когда
открывают PR. Пустой `push:` без значений означает «на каждое событие этого
типа».

**`jobs:`** — задачи. Их может быть несколько, они идут параллельно.

**`runs-on:`** — на какой машине выполнять. `ubuntu-latest` — стандартный
Linux. Бывают `windows-latest` и `macos-latest`, они медленнее и дороже.

**`steps:`** — шаги внутри задачи, по порядку. Ошибка в шаге останавливает
весь job.

**`uses:`** — готовое действие, написанное кем-то ещё. `actions/checkout`
забирает код на машину; без неё папки с кодом просто не будет.

**`run:`** — команда, которую надо выполнить. Обычная строка или блок:

```yaml
      - name: Несколько команд
        run: |
          bash -n labs/*/*/check.sh
          python3 tools/check_content.py
```

Блок `|` в YAML означает «многострочное значение».

## Что стоит проверять в первом очередь

Порядок полезности, а не сложности:

1. **Синтаксис скриптов.** `bash -n` ничего не выполняет, только ищет опечатки.
   Самая дешёвая проверка, ловит много.
2. **Проверка материалов.** У нас есть `tools/check_content.py` — битые ссылки,
   рассинхрон языков, отсутствующие файлы.
3. **Собственно практики.** Их нельзя запустить целиком: им нужны ученические
   файлы. Но можно проверить, что пустое состояние честно падает.
4. **Оформление.** Пробелы, табы, перевод строки. Для `*.sh` обязателен LF:
   CRLF даёт `$'\r': command not found`.

## Секреты

Любой токен, ключ и пароль — через `secrets`, никогда текстом в файле:

```yaml
      - name: Войти
        run: gh auth login --with-token <<< "$TOKEN"
        env:
          TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

Файл с секретом в репозитории означает, что его надо менять немедленно, даже
если удалить коммит. Git хранит историю.

## Отладка

Если прогон упал — смотри лог конкретного шага. Частые причины:

- забыт `actions/checkout`, и папки с кодом нет;
- скрипт не исполняемый — нужен `chmod +x` или запуск через `bash`;
- в скрипте CRLF вместо LF;
- команда вернула ненулевой код, а ты этого не ожидал.

Ошибка видна построчно. Не угадывай — читай лог.

## Ограничение, которое надо понимать

Бесплатные минуты для публичных репозиториев щедрые, для приватных —有限 и
общие на аккаунт. Наш учебный репозиторий публичный, поэтому ограничений
почти нет. Не закладывай Actions как постоянную тяжёлую вычислительную задачу.
