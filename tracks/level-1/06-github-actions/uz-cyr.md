# Дарс 6. GitHub Actions

## Бу нима

GitHub Actions — сизнинг кодингизни сизнинг ўрнингизда бажарадиган
компьютер. Репозиторияга нима қилиш кераклигини ёзиб қўясиз, GitHub эса ҳар
бир пушда буни ўз компьютерингизсиз бажаради.

```
сиз код пуш қиласиз  →  GitHub сезади  →  виртуал машина ишга тушади
                     →  буйруқларни бажаради  →  натижани кўрсатади
```

Асосий фойда: **текширув кимнинг эслаб қолишига боғлиқ эмас.** Кимдир
бузилган кодни пуш қилса — дарҳол бузилади. Ва ҳаммада бир хил бузилади.

## Файл қаерда бўлади

`.github/workflows/ном.yml` репозитория илдизида. Ном иxtiyoriй, кенгайтма
`yml` ёки `yaml`. `.github/workflows/` ичидаги ҳамма нарса автоматлаштириш
таъсифи деб ҳисобланади.

Бу **оддий матн**, сир эмас. Очиб, ўқиб, қўлда тузатиш мумкин.

## Минимал workflow

```yaml
name: Текширув

on:
  push:
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - name: Кодни олиш
        uses: actions/checkout@v4

      - name: Лабораторияни текшириш
        run: ./labs/level-0/01-terminal/check.sh
```

Қатор қатор кўриб чиқамиз.

**`name`** — интерфейсда иш номи.

**`on:`** — қачон ишга тушсин. `push` — ҳар бир пушда, `pull_request` —
PR очилганда. Бўш `push:` «шу турдаги ҳар бир ҳодисада» дегани.

**`jobs:`** — вазифалар. Бир нечта бўлиши мумкин, улар параллел ишлайди.

**`runs-on:`** — қайси машинада. `ubuntu-latest` — стандарт Linux.
`windows-latest` ва `macos-latest` ҳам бор, улар секинроқ ва қимматроқ.

**`steps:`** — job ичидаги қадамлар, кетма-кет. Хатолар битта қадам бутун
jobни тўхтатади.

**`uses:`** — тайёр амал, бошқа томонидан ёзилган. `actions/checkout` коди
машинага олиб келади; у бўлмаса код папкаси умуман бўлмайди.

**`run:`** — бажариладиган буйруқ. Бир қатор ёки блок:

```yaml
      - name: Бир нечта буйруқ
        run: |
          bash -n labs/*/*/check.sh
          python3 tools/check_content.py
```

YAML да `|` блок «кўп қаторли қиймат» дегани.

## Аввал нима текширилади

Фойдалилик бўйича тартиб, муракоблик бўйича эмас:

1. **Скрипт синтаксиси.** `bash -n` ҳеч нарсани бажармайди, фақат хатоларни
   қидиради. Энг арзон текширув, кўпини ушлайди.
2. **Материаллар валидатори.** Бизда `tools/check_content.py` бор — ўлган
   ҳаволалар, тил мослигининг бузилиши, йўқ файллар.
3. **Лабораторияларнинг ўзи.** Уларни тўлиқ ишга тушириб бўлмайди:
   ўқувчи файллари керак. Лекин бўш ҳолат ҳалол йиқилишини текшириш мумкин.
4. **Кўриниш.** Бўшлиқлар, таблар, сатр охири. `*.sh` учун LF мажбурий:
   CRLF `$'\r': command not found` беради.

## Махфий маълумотлар

Ҳар қандай токен, калит ва парол — `secrets` орқали, ҳеч қачон файлда
матн сифатида эмас:

```yaml
      - name: Кириш
        run: gh auth login --with-token <<< "$TOKEN"
        env:
          TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

Репозиторияда махфий файл бўлса, уни дарҳол алмаштириш керак — коммитни
ўчирсангиз ҳам. Git тарихни сақлайди.

## Носозликни тузатиш

Иш йиқилса — айнан шу қадам логини ўқинг. Кўп учраган сабаблар:

- `actions/checkout` унутилган, код папкаси йўқ;
- скрипт бажарилмайди — `chmod +x` керак ёки `bash` орқали ишга туширинг;
- скрипт ичида CRLF, LF эмас;
- буйруқ нолга тенг бўлмаган натижа берди, сиз кутангансиздан фарқли.

Хатолар қатор қатор кўринади. Тахмин қилманг — логни ўқинг.

## Тушуниш керак бўлган чегара

Оммавий репозиториялар учун бепул дақиқалар кенг, шахсийлар учун
чекланган ва ҳисоб бўйича умумий. Бизнинг ўқув репозиториямиз оммавий,
шунинг учун чегара амалда йўқ. Actionsни доимий оғир ҳисоблашга
режалаштирманг.
