# Дарс 5. Иш билан GitHub

## Бу дарс нима беради

Олдинги дарсда сен git билан маҳаллий ишлаган: коммит қилдингиз, тармоқ
яратдингиз, қайтариб merge қилдингиз. Бу тарих ҳеч қаерга кетмаган — сенинг
машинангиздаги папкада яшаган.

GitHub учта нарсани қўшади, улар gitда йўқ:

1. **умумий кириш** — тарихни бошқалар кўради;
2. **муҳокама** — код ёнида савол бериш ва жавоб бериш мумкин;
3. **текширувлар** — автоматик код «бузилди» деб айта олади.

GitHubсиз git шахсий дафтарда қолади. У билан бирга — бирга ишлаш усули
бўлади.

## Fork ва clone: фарқи

**Fork** — бошқанинг репозиториясининг сенгиз GitHub ҳисобингиздаги нусхаси.
Uni бир тугма билан олдингиз, код жисман кўчирилмаган — бу GitHub серверидаги
ёзув.

**Clone** — сенгиз машинангиздаги нусха, `git clone` орқали юкланган.

Тартиб доим бир хил:

```
бошқа репо  →  сенгиз форк  →  машинага clone
```

Асл репони тўғридан-тўғри clone қилишингиз мумкин, лекин кейин push қила
олмайсиз: бошқанинг репозиториясига ҳуқуқингиз йўқ. Fork айнан шунинг учун
керак.

```bash
git clone https://github.com/<сизнинг-логин>/hackerspace-tashkent-learning.git
```

Манзилга бўринг — **сизнинг логинингиз**, `Hackerspace-Tashkent` эмас. Агар
`git remote -v` да асл репо чиқса, форк қилмагансиз ёки нотўғри нарсани
клонлагансиз.

## remote: push қаерга кетади

```bash
git remote -v
origin  https://github.com/<сизнинг-логин>/... (fetch)
origin  https://github.com/<сизнинг-логин>/... (push)
```

`remote` — бу шунчаки манзил учун ном. Улар қанча бўлиши мумкин:

```bash
git remote add upstream https://github.com/Hackerspace-Tashkent/hackerspace-tashkent-learning.git
```

`origin` — сенгиз форк, push шу ерга. `upstream` — асл репо, бошқаларнинг
ўзгаришлари шу ердан келади. `push` да `origin` ишлатилади:

```bash
git push origin my-branch
```

## Тармоқ ва асл репо билан мослашиш

Сен доим тармоқда ишлайсан, `main` га тегмайсан:

```bash
git switch -c add-my-note
```

Асл репо ҳаётда давом этса, сенгиз форк орқада қолади. Ўзгаришларни олинг:

```bash
git fetch upstream
git switch main
git merge upstream/main
git switch add-my-note
git merge main
```

Охирги икки команда `main` ни сенгиз тармоғингизга улайди, шунда улар ажралиб
кетмайди. Агар тармоғингизда айнан шу қаторлар ўзгарган бўлса — Git конфликт
кўрсатади. Бу бузилган эмас, бу «нима қолади?» деган қўлда қарор.

## Pull request

**Pull request (PR)** — «менинг ўзгаришларим, қаранг ва уланг» таклифи.

Расмий равшанда PR «бирлаштириш сўрови» эмас, балки **текшириш сўрови**.
Бирлаштириш умуман бўлмаслиги мумкин: одам ўзгартириш сўрайди. Шунинг учун
Merge тугмасидан кўра тавсиф муҳимроқ.

Тавсиф одамга мурожаат қилади. Камда:

```markdown
## Нима ўзгартирилди
## Қандай текширилади
## Мен ўзим нимани текширдим
```

Учинчи пункт шакл бўйича шарт эмас, лекин қолганларидан қимматлироқ.
Муаллиф тугмани босганини эмас, текширганини кўрсатади.

Браузер орқали: push → GitHub «Compare & pull request» тугмасини кўрсатади.
Терминал орқали, `gh` бўлса:

```bash
gh pr create --fill
gh pr status
```

## Issue: кодсиз суҳбат

Issue — бу ариза, савол ёки ғоя. Унда код умуман бўлмаслиги мумкин.

Issue ва PR — турли нарсалар, гарча иккаласи GitHubда яшайди:

| | Issue | Pull request |
|---|---|---|
| Нима ҳақида | савол, ғоя, хато | кодга аниқ ўзгаришлар |
| Коди бор | шарт эмас | шарт |
| Ким ёпади | муаллиф ёки maintainer | review'дан кейин maintainer |

Тайёр тузитилмаган хато — issue. Тайёр тузитилгани — PR, унинг тавсифида
муҳокама қилинган issuega ҳавола қилинади.

Яхши issue: нима кутилган, нима бўлган, қандай такрорлаш мумкин.

## Review

Review — бошқанинг ўзгаришини ўқиб, жавоб бериш. Бу услуб текшируви эмас,
бу «буни тўғри қилдимми?» текшируви.

Фойдали review учта саволга жавоб беради:

- **нима ўзгаргани ва нима учун тушунарли** (коддан эмас, тавсифдан);
- **ҳақиқатан тўғри ишлайдими** (текшириш йўли борми);
- **нима ҳисобга олинмаган** (бошқаларда нима бузилади).

Ёрдам бермайдиган иборалар: «тузат», «ёмон», «роzi эмасман». Ёрдам беради:
«бу ҳолат йиқилади, чунки…», «бўш қиймат бу ерда қайта ишланмаган, мана
мисол».

Биз расмий қоидалар талаб қилмаймиз. Бир нарсани талаб қиламиз:
**изоҳ нима нотўғри ва нима яхши бўлишини тушунтириши керак.** Келишмовчилик
нормал, агар сабаби ёзилган бўлса.

## Ҳозироқ созланадиган икки нарса

Бу иккисини дарҳол қилинг, кейин ҳайрон бўлмаслик учун:

```bash
git config --global user.name "Сенгиз Исмингиз"
git config --global user.email "сенгин@почта"
```

Буларсиз коммитлар `root` номи билан имзоланади ёки Codespaces'да умуман
яратилмайди.

Иккинчиси — `.gitignore`. Унга тарихга кирмаслиги керак бўлган ҳамма нарса
тушади: `lab-work/`, калитлар, `.env`, вақтинчалик файллар. Бизнинг
репозиторияда аллақачон созланган, лекин ўз форкингизда рўйхат мос келишини
текширинг.

файлларнинг жойида ва тўғри топширилгани.
