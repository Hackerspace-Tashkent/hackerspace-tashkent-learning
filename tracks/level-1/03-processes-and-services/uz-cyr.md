# 7-дарс. Жараёнлар ва хизматлар

Ҳар бир ишлаётган дастур — рақамли жараён. Уларни кўриш, фонга ўтказиш ва одоблик тўхтатиш — ишлаётган машина ва тушумсиз машина ўртасидаги фарқ.

## Жараёнларни кўриш

```bash
ps                  # процессы текущего терминала
ps aux               # все процессы всех пользователей
ps -ef               # то же, другой формат
top                  # обновляется live, q — выход
pgrep -f "python"    # найти по имени
```

Ҳар бир жараённинг `/proc` да шу рақамда каталоги бор. Бу дастур ўзи ҳақида нима деганини кўришнинг ҳалол йўли.

## Фон ва тўхтатиш

```bash
sleep 300 &        # запустить в фоне
jobs                # что запущено из этого терминала
nohup ./long.sh &   # пережить закрытие терминала
disown -a           # забыть о фоновых процессах

kill 12345          # попросить завершиться (SIGTERM)
kill -9 12345       # убить немедленно (SIGKILL)
```

> **Изоҳ.** К ҳарфи катта емас `kill` — ҳазил емас: оддий `kill` йахшилаб сўрайди. `-9` ушланмайди, дастур тозалашга улгурмайди.

## Сигнални ушлаб олиш

`trap` скриптга тўхтатилганда ўз тозалашини бажаришга имкон беради. Акс ҳолда йарим йозилган файл йарим қолади.

```bash
#!/usr/bin/env bash
tmp="work.tmp"

cleanup() {
  echo "cleaning up..."
  rm -f "$tmp"
}
trap cleanup EXIT TERM

echo "working" > "$tmp"
sleep 30
```

> **Изоҳ.** Фақат логга йозиб қайтадиган trap йетарли емас: сикл давом етаверади ва жарайон тугамайди. Йозинг ва ҳандлер ичида `exit 0` қилинг. Йана еслаб қолинг: bash trapни жорий буйруқ тугагандан кейин бажаради — `sleep 300` ичидаги скрипт `kill` ни беш дақиқага етиборсиз қолдиради. Шунинг учун амалийотда қисқа паузалар ишлатилади.

## systemd ва хизматлар

Ҳақиқий Linux машинасида `systemd` дастурларни йукланганда ишга туширади, қулангандан кейин қайта ишга туширади ва уларнинг чиқимини йиғади. Хизмат юнит файли билан тасвирланади.

```ini
[Unit]
Description=My report service
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/report.sh
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Йуклаш — `systemctl daemon-reload`, ишга тушириш — `systemctl start report`, кузатиш — `journalctl -u report -f`.

> **Изоҳ.** Codespace — контейнер, у йерда `systemd` ПИД 1 емас ва `systemctl status` ишламайди. Шунинг учун амалийот хизмат йуришини емас, юнит файлининг тўғрилигини текширади.

## Амалиёт

1. `lab-work` каталогини йаратинг.
2. `worker.sh` йозинг: бир дақиқа сиклда ишлайди, ҳар сонийада `worker.log` га қатор йозади ва ТЕРМ сигналини trap орқали ушлаб, йакуний қатор йозиб, сўнг чиқади.
3. Уни фонда ишга туширинг, ПИД ни `worker.pid` га сақланг ва журнал ўсайотганини тасдиқланг.
4. Бир неча сонийа кутиб, `kill` билан йахшилаб тўхтатинг. `worker.log` охирида тозалаш қатори борлигини ва жарайон қолмаганини текширинг.
5. Жарайон йўқлигини `kill -0 <pid>` билан текширинг.
6. `Unit`, `Service` ва `Install` бўлимлари бўлган `worker.service` systemd унитини йозинг, ЕхецСтарт еса скриптингизнинг абсолйут йўлини кўрсацин.
