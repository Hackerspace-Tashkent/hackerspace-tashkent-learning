# Урок 6. Автоматизация и журналы

Задача, которая выполняется сама, стоит намного больше, чем задача, которую надо помнить. Этот урок — о том, как включить расписание и оставить след.

## Потоки вывода

У каждой команды три потока: стандартный вывод для результата, стандартный вывод ошибок для проблем и стандартный ввод. `>` пишет файл, `>>` дописывает, `2>` перенаправляет ошибки.

```bash
ls > out.txt          # только stdout, очистит файл
ls >> out.txt         # добавит в конец
ls 2> err.txt         # только stderr
ls > all.txt 2>&1     # и то и другое в один файл
ls 2>&1 | grep txt    # ошибки тоже попадут в пайп
```

> **Заметка.** Журнал — это файл, в который дописывают и никогда не очищают. Используй `>>` и ставь дату в начало каждой строки.

```bash
#!/usr/bin/env bash
log="run.log"
printf '%s started\n' "$(date '+%F %T')" >> "$log"
printf '%s finished with code %d\n' "$(date '+%F %T')" "$?" >> "$log"
```

## Расписание через cron

`cron` запускает команду в заданное время. В строке пять полей: минута, час, день месяца, месяц, день недели, затем сама команда.

```bash
# минута час день месяц день_недели  команда
*/5 *   *   *     *            /home/me/report.sh
0  9   *   *     1-5          /home/me/backup.sh
30 18  *   *     *            /home/me/clean.sh
```

Никогда не давай cron слать почту. Лучше перенаправить оба потока в файл журнала.

```bash
*/10 * * * * /home/me/report.sh >> /home/me/report.log 2>&1
```

## Правка расписания

```bash
crontab -l     # показать текущие задачи
crontab -e     # изменить
crontab -r     # удалить все (осторожно)
```

Crontab — это просто текстовый файл, по задаче на строку. `crontab myfile` устанавливает его, `crontab -l` показывает, что установлено. Хранить расписание в файле, а не редактировать вслепую внутри `crontab -e`, значит держать его в git и переносить на любую машину.

> **Заметка.** В Codespace демон `cron` не запущен, поэтому установленные задачи сами не сработают. Практика работает с файлом: напиши расписание и проверь, что файл верный. Установка и наблюдение — это то, что ты сделаешь на реальной машине.

## Практика

1. Создай каталог `lab-work`.
2. Напиши `report.sh`, который при каждом запуске дописывает одну строку с датой в `run.log`.
3. Запусти три раза. В `run.log` должно быть ровно три строки, и все они должны начинаться с даты.
4. Напиши `task.sh`, который всегда завершается с кодом 0, даже если команда внутри упала.
5. Напиши `crontab.txt` — crontab в файле — который запускает `task.sh` каждые 10 минут, оба потока в `cron.log`. Используй абсолютный путь к скрипту.
6. Установи его один раз через `crontab crontab.txt` и посмотри через `crontab -l`.
