# Дарс 7. GitHub Pages

## Бу нима

GitHub Pages — репозиториядан тўғридан-тўғри статик сайт хостинги. Сиз
илдизга `index.html` файлини қўясиз, созламаларда Pages ни ёқасиз, бир дақиқадан
кейин сайт манзилда очилади.

```
репозитория  →  Pages ни ёқиш  →  GitHub йиғади  →  сайт ишлайди
```

Бизнинг сайтимиз айнан шундай қурилган:
`https://hackerspace-tashkent.github.io/Hackerspace-Tashkent-website/`.

## Асосий чегара

Pages фақат **статик файлларни** беради. Яъни `.html`, `.css`, `.js`, расм ва
шрифтлар.

У нима **қила олмайди**:
- серверда код ишга тушириш — на PHP, на Python, на Node;
- базани сақлаш;
- ташқи сервиссиз шакл қабул қилиш;
- махфий маълумотларни яшириш — репозиториядаги ҳамма нарса ҳаммага кўринади.

Шундан қоида: **сервер мантиғи — бу VPS, статика — бу Pages.** Агар сайтга база
керақ бўлса, икки йўл бор: ташқи сервис (Supabase, Airtable) ёки ўз серверингиз.
Pages да API калитини яшириш умуман мумкин эмас, махфий калит ҳар доим саҳифа
манбасида кўринади.

## Биринчи усул: тармоқдан

Энг оддий ва кўпинча етарли.

1. `index.html` файли `main` илдизида туради.
2. **Settings → Pages → Source: Deploy from a branch**, тармоқ `main`, папка
   `/ (root)`.
3. Сақланг. Бир-уч дақиқадан кейин сайт жавоб беради.

Муҳим тафсилотлар:
- файл **аниқ `index.html`** деб номланиши керак (`index.htm` эмас, `Index.html`
  ҳам эмас);
- сайт ички папкада бўлса, манзилда `/папка-номи/` кўринади;
- бош саҳифа — `index.html`, қолгани файл номи билан очилади.

## Иккинчи усул: Actions орқали

Керак, агар сайт йиғилади: статик сайт генератори, шаблонлар, расмларни
қайта ишлаш.

```yaml
name: Сайтни эълон қилиш

on:
  push:
    branches: [main]

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: '.'
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
    steps:
      - uses: actions/deploy-pages@v4
```

Бу ерда муҳим ва очиқ бўлмаган нарса:

**`permissions:`** — Actions саҳифаларни сукут бўйича эълон қила олмайди. Бу
уч қаторсиз деплой ҳуқуқ хатоси билан тўхтайди.

**Иккита job, биттаси эмас.** Йиғиш ва эълон қилиш ажратилган: қайта йиғиш
ишлаётган сайтни бузмасин. `needs: build` «биринчисини кут» дегани.

**`environment: github-pages`** — GitHub ўзи яратадиган махсус муҳит. Айнан у
деплойни Pages га боғлайди.

**Артефакт** — оралиқ натижа. `upload-pages-artifact` папкани йиғади,
`deploy-pages` уни очиб жойлайди.

## Ўз доменингиз

**Settings → Pages → Custom domain** га доменингизни ёзинг, сўнги домен
созламаларингизда `USER.github.io` га CNAME яратинг.

Икки огоҳлантириш:
- домен дарҳол ишга тушмайди; текширув дақиқалардан бир кунгача, баъзан
  узоқроқ давом этади;
- DNS созланмаган бўлса, сайт `DNS Check in Progress` ҳолатида туриб қолади ва
  очилмайди. Нимадан кейин кутишдан олдин домен умуман resolve бўлишини
  текширинг.

Биз шу ерга урилдик: `hackerspace.uz` созланмаган ва очилмайди. Ишлайдиган
манзил — Pages даги.

## Эълон қилишдан олдин маҳаллий текшириш

Эълон қилиб, кейин қориш — ёмон цикл. Маҳаллий текширинг:

```bash
cd lab-work
python3 -m http.server 8000
```

Браузерда `http://127.0.0.1:8000` ни очинг. Маҳаллий ишлайди, Pages да
ишлагмаса — муаммо Pages созламасида, кода эмас.

Codespaces ҳам шундай: у ерда портга «Open in Browser» тугмаси бор.

## HTTPS

Pages сертификатни автоматик беради. Мажбурий HTTPS — созламадаги тугма. Ўз
доменингизда «Enforce HTTPS» ни ёқишингиз мумкин, лекин аввал домен
очилишини таъминланг — акс ҳолда ҳеч кимга кўринмайдиган сайт ҳосил бўлади.
