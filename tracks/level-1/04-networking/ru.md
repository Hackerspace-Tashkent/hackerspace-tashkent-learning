# Урок 8. Сеть

Сервер — это просто программа, которая слушает порт. Когда ты умеешь её запустить и к ней обратиться, сеть перестаёт быть магией.

## Адреса и порты

```bash
ip addr              # адреса всех интерфейсов
ip route             # куда идёт трафик
hostname -I          # свой адрес
ss -tlnp             # кто слушает порты
```

`127.0.0.1` — это `localhost`, ты говоришь сам с собой. Порт — число от 1 до 65535, которое выбирает одну программу из слушающих.

## Запуск сервера

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

Бери порт выше 1024 — ниже нужен root. `--bind 127.0.0.1` оставляет сервер доступным только с этой же машины, и это безопасный вариант по умолчанию.

## Обращение к серверу

```bash
curl -I http://127.0.0.1:8000     # только заголовки
curl -s http://127.0.0.1:8000 | head    # первые строки
curl -o page.html http://127.0.0.1:8000 # сохранить в файл
echo $?                                # код: 0 — связь есть
```

- `200` OK
- `301` или `302` перенаправление
- `404` не найдено
- `403` запрещено
- `000` соединение не удалось

## Имена вместо адресов

Хост — имя, указывающее на адрес. `/etc/hosts` — небольшой локальный список, его проверяют раньше, чем спросят DNS.

```bash
echo "127.0.0.1  mysite.local" | sudo tee -a /etc/hosts
curl -I http://mysite.local:8000
```

## Если `ip` и `ss` не нашлись

Команды `ip` и `ss` живут в пакете `iproute2`. В некоторых сборках
Codespaces его нет, и ты увидишь:

```bash
ip: command not found
```

Это не поломка урока. Есть запасной путь:

```bash
hostname -I          # свой адрес — есть всегда
cat /proc/net/tcp    # открытые порты — тоже всегда
```

Разобраться в выводе `/proc/net/tcp` сложнее, чем в `ss`, поэтому учебной
задачей останется `hostname -I`. Установить недостающее можно так:

```bash
sudo apt-get install -y iproute2
```

## Практика

1. Создай каталог `lab-work` и положи в него файл `index.html` с любым текстом.
2. Напиши `serve.sh`: запускает `python3 -m http.server` на порту 8000 в фоне и пишет PID в `server.pid`.
3. Запусти, затем сохрани код ответа в `status.txt`: `curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8000 > status.txt`.
4. Убедись, что порт есть в выводе `ss -tlnp` (или `netstat -tlnp`), и сохрани эту строку в `ports.txt`.
5. Напиши `check_site.sh`: запрашивает указанный порт и завершается с 0 только при статусе 200, иначе с 1. На неверном порте должен дать 1.
6. Останови сервер через `kill`, взяв PID из `server.pid`, и убедись, что на 8000 больше никто не слушает.

```bash
cd labs/level-1/04-networking
./check.sh
```
