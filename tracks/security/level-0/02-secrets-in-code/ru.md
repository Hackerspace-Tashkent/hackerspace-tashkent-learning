# Секрет в коде

## Зачем это знать

Есть вещь, которую понимают почти все разработчики и почти никто из
начинающих. Вот сценарий:

```text
закоммитил код с ключом  →  убрал ключ из файла  →  закоммитил снова
```

В этот момент человек уверен, что ключ исчез. **Он не исчез.** Он
остался в истории, и любой, у кого есть копия репозитория, достанет его
одной командой.

Секрет считается скомпрометированным с момента, когда попал в историю.
Не с момента, когда его оттуда убрали.

## Что сделает практика

Тебе дадут репозиторий с историей из двух коммитов:

- первый — ключ лежит прямо в `app.py`;
- второй — ключ убрали и перенесли в переменную окружения.

Ключ называется `vt-lark-tessera-5Q2fK`. Это **выдуманное** имя: такого
сервиса не существует, ключ нельзя загуглить. И ты его не выбирал —
значит, найти его можно только разобравшись.

## Порядок работы

1. Подготовь фикстуру:

```bash
bash setup-repo.sh
```

2. Посмотри текущее состояние — ключа там уже нет:

```bash
cd lab-work/repo
cat app.py
```

3. Найди его в истории:

```bash
git log --oneline
git log -p
git log -p | grep -i token
```

4. Есть и другие способы — попробуй их все, это и есть навык:

```bash
git log -S'vt-lark' --oneline
git rev-list --all | while read c; do git grep -l 'vt-lark' "$c"; done
```

5. Убедись, что в текущей версии ключа нет:

```bash
grep -rn 'vt-lark' . || echo "в текущей версии чисто"
```

6. В `lab-work/proof.txt` запиши хеш найденного ключа — первые 12
символов sha256:

```bash
printf '%s' 'vt-lark-tessera-5Q2fK' | sha256sum | cut -c1-12 > ../proof.txt
```

7. Ответь в `lab-work/notes.md` — **что нужно сделать, чтобы ключ
   действительно перестал существовать?**

   Ты сейчас находишься в `lab-work/repo`. Путь до файла оттуда —
   `../notes.md`.

## Ответ, к которому стоит прийти

Текущий файл чист — и это ничего не меняет. История хранит **все**
версии, включая удалённые. Варианты:

- **сменить ключ** — единственное настоящее решение. Старый считается
  скомпрометированным, потому что он в истории;
- переписать историю (`git filter-repo`, BFG) — удалит след из
  репозитория, но не отменит того, что ключ уже где-то побывал;
- если репозиторий уже форкнули или клонировали — след ушёл к другим
  людям, и переписывание истории ничего не даёт.

Отсюда правило: **секреты не кладут в репозиторий вообще.** Файл
`.gitignore` помогает от файлов, но не спасает от внимательности —
достаточно одного `git add -f`.

## Где секрету место

| Где | Подходит |
|---|---|
| переменная окружения | да |
| файл, которого нет в git | осторожно: он может попасть в сборку |
| менеджер секретов | да |
| прямо в коде | нет |

Обрати внимание на урок про ИИ: там отдельно сказано, что в чат с
нейросетью код с секретами не кладут. Это тот же случай.

## Важно

Репозиторий здесь свой, лежит в твоей лабораторной папке, и ключ в нём
выдуманный. На настоящих ключах так не экспериментируют — их просто
не кладут туда, где они могут утечь.
