# Коди ичидаги сир

## Буни нега билиш керак

Деярли барча дастурчилар тушунадиган, лекин янги бошловчи тушунмайдиган
нарса бор. Мана сценарий:

```text
калит билан кодини коммит қилди  →  калитни файлдан олиб ташлади  →  яна коммит қилди
```

Бу нуқтада одам калит йўқлигига ишонади. **У йўқ эмас.** У тарихда
қолади, ва репозиторий нусхаси бор ҳар ким уни битта буйруқ билан
чиқариб олади.

Сир тарихга кирган заҳоти ошкор ҳисобланади — олиб ташлаган заҳоти
эмас.

## Амалиёт нимани беради

Иккита коммитли репозиторий:

- биринчиси — калит тўғри `app.py` ичида;
- иккинчиси — калит олиб ташланиб, муҳит ўзгарғучисига кўчирилган.

Калит `vt-lark-tessera-5Q2fK`. Бу **ишонтирилган** ном: бундай хизмат
йўқ, калитни интернетдан топиб бўлмайди. Ва сен уни танлаган эмас —
демак, уни фақат тушуниб олиш йўли бор.

## Иш тартиби

1. Фикстурани тайёрла:

```bash
bash setup-repo.sh
```

2. Жорий ҳолатни кўр — калит унда йўқ:

```bash
cd lab-work/repo
cat app.py
```

3. Уни тарихда топ:

```bash
git log --oneline
git log -p
git log -p | grep -i token
```

4. Бошқа йўллар бор, уларни ҳам синаб кўр — бу ҳам малака:

```bash
git log -S'vt-lark' --oneline
git rev-list --all | while read c; do git grep -l 'vt-lark' "$c"; done
```

5. Жорий версияда калит йўқлигини текшир:

```bash
grep -rn 'vt-lark' . || echo "жорий версия тоза"
```

6. `lab-work/proof.txt` да топилган калитнинг хешини ёз — sha256 нинг
   биринчи 12 белгиси:

```bash
printf '%s' 'vt-lark-tessera-5Q2fK' | sha256sum | cut -c1-12 > ../proof.txt
```

7. `notes.md` да жавоб бер: **калит ҳақиқатан йўқ бўлиши учун нима
   қилиш керак?**

## Етиб ориладиган жавоб

Жорий файл тоза — бу ҳеч нарсани ўзгартирмайди. Тарих **барча**
версияларни сақлайди, ўчирилганларини ҳам. Вариантлар:

- **калитни алмаштириш** — ягона ҳақиқий ечим. Эскиси тарихда бўлгани
  учун ошкор ҳисобланади;
- тарихни қайта ёзиш (`git filter-repo`, BFG) — изни репозиторийдан
  олиб ташлайди, лекин калит аллақачон бирор жойга бориб кетганини
  бекор қилмайди;
- репозиторий аллақачон форкланган ёки клонланган бўлса — из бошқаларга
  кетган, тарихни қайта ёзиш фойда бермайди.

Шундан қоида: **сирлар репозиторийга умуман қўйилмайди.** `.gitignore`
файлларга ёрдам беради, лекин эътиборсизликдан ҳимоя қилмайди — бир
`git add -f` ерта кетади.

## Сир қаерда бўлиши керак

| Қаерда | Мос келадими |
|---|---|
| муҳит ўзгарғучиси | ҳа |
| gitга кирмайдиган файл | эҳтиёт бўлинг: сборкага тушиши мумкин |
| сирлар менеджери | ҳа |
| тўғридан-тўғри кодда | йўқ |

СИИ ҳақидаги дарсга эътибор бер: унда алоҳида айтилганки, сирли
кодни суҳбатга қўйиш мумкин эмас. Бу ҳам шу ҳолат.

## Муҳим

Бу ердаги репозиторий сизники, лаборатория папкасида турибди, калит
ишонтирилган. Ҳақиқий калитлар билан шундай қилинмайди — уларни
одимга тушиши мумкин бўлган жойга қўймайди.
