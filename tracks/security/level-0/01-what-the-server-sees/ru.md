# Что сервер видит

## Зачем это знать

Когда ты отправляешь запрос, ты отправляешь **больше, чем думаешь**.
Кроме написанного тобой там есть имя браузера, версия, иногда язык,
иногда данные о том, откуда пришли.

Сервер видит всё это. **И он этому верит.**

Отсюда следует то, что сбивает с толку новичков: **любое утверждение о
том, кто ты, пришедшее от клиента, доказательством не является.**

## Три части запроса

```text
GET /readings HTTP/1.1
Host: 127.0.0.1:8000
X-Debug: 1
X-Access-Key: sable-marmalade
```

- **метод** — что ты хочешь сделать;
- **путь** — над чем;
- **заголовки** — всё остальное. И подделываются они легко.

Заголовок — просто пара «имя: значение». Написать свой можно любой
командой `curl`, браузер для этого не нужен.

## Что ты соберёшь

Сервер на `127.0.0.1:8000` с таким поведением:

- `/health` — отвечает всегда, но **если прислать заголовок
  `X-Debug: 1`, отдаёт внутренний ключ**. Для настоящей системы это
  неправдоподобно: так бывает, когда отладку забыли выключить;
- `/readings` — отдаёт данные, **но только с правильным `X-Access-Key`**;
- без ключа — `403`.

Создай `lab-work/srv.py`:

```python
#!/usr/bin/env python3
"""Сервер-заглушка. Он доверяет заголовкам — это и есть проблема."""
import json
from http.server import BaseHTTPRequestHandler, HTTPServer

# Выдуманное имя: в интернете такого нет, ключ нельзя загуглить.
ACCESS_KEY = "sable-marmalade-4710"
DATA = [{"time": "12:00", "pm25": 42.3}, {"time": "12:05", "pm25": 39.8}]


class Handler(BaseHTTPRequestHandler):
    def reply(self, code, payload):
        body = json.dumps(payload, ensure_ascii=False).encode("utf-8")
        self.send_response(code)
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def do_GET(self):
        # Заголовок прислал клиент. Сервер ему верит.
        # В настоящей системе такого быть не должно.
        if self.headers.get("X-Debug") == "1":
            return self.reply(200, {"status": "ok", "debug_key": ACCESS_KEY})

        if self.path == "/readings":
            if self.headers.get("X-Access-Key") == ACCESS_KEY:
                return self.reply(200, {"readings": DATA})
            return self.reply(403, {"error": "key required"})

        self.reply(404, {"error": "not found"})


HTTPServer(("127.0.0.1", 8000), Handler).serve_forever()
```

## Порядок работы

1. Запусти `python3 srv.py` в отдельном терминале.
2. Спроси без ничего:

```bash
curl -s http://127.0.0.1:8000/health
```

3. Спроси с заголовком отладки:

```bash
curl -s -H 'X-Debug: 1' http://127.0.0.1:8000/health
```

4. Возьми значение оттуда и открой данные:

```bash
curl -s -H 'X-Access-Key: <значение>' http://127.0.0.1:8000/readings
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8000/readings
```

Без ключа вернётся `403`.

5. В `notes.md` ответь: **почему сервер вообще отдал ключ?**

## Доказательство, а не галочки

В `proof.txt` запиши **хеш найденного ключа**: первые 12 символов sha256
от него, строчными.

```bash
printf '%s' 'ключ' | sha256sum | cut -c1-12 > proof.txt
```

Проверка достанет ключ сама, пересчитает хеш и сравнит. Подсмотреть
нечего: его нет ни в уроке, ни в `check.sh`.

## О чём это на самом деле

Ты обошёл «защиту», которой **не существовало**. Сервер думал, что
заголовок `X-Debug` ставит только он сам. Но заголовок ставит тот,
кто спрашивает.

Подделывание личности, обход прав доступа и многое другое построены на
этом же принципе. Мысль одна: **клиент не является источником истины**.

## Важно

Всё происходило на твоей машине, на `127.0.0.1`, с сервером, который ты
написал сам. **Только так это и допустимо.** Тот же приём против чужого
сервера — не обучение.
