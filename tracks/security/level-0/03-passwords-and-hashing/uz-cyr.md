# Пароллар ва хешлар

## Буни нега билиш керак

Хеш — бу **шифрлаш эмас**. Шифрлаш қайтарилади: калит бор, асл матн
қайтади. Хеш қайтарилмайди: `a94f8f5` дан `sable` ни олиб бўлмайди.

Бу яхши ҳам, ёмон ҳам. Яхши — чунки паролни ўқиб бўлмайди.
Ёмон — чунки **эслаб қолган паролни тиклаш умуман мумкин эмас**,
фақат янгилаш мумкин.

## Бу қандай бузилади

Йиллар давомида пароллар шундай сақланарди:

```python
hashlib.sha256(password.encode()).hexdigest()
```

Бу ердан келиб чиқадиган натижалар.

**Бир хил пароллар бир хил хешларни беради.** Иккита одамда `123456`
бўлса, оқиб чиққан файлда икки хил хеш бўлади. Хешнинг ўзидан
паролни нечта одам ишлатанини айтиб ҳам бўлмайди.

**Ташлаш жадвал билан мулоқотга айланади.** Кимдир олдиндан
миллиардлаб оддий паролларнинг хешларини ҳисоблаб қўяди — буни
рангин жадвал дейилади. Кейин олинган файлни бошқариб текширилмайди,
**тайёр жадвалда қидирилади**: мос келса — парол маълум.

**Тезлик чекланмаган.** sha256 секундда миллиард марта ҳисобланади.
Сен бир миллиард вариантни текшириб тугамасдан ҳеч ким сезирмайди.

## Бунинг ечими бор

**Туз.** Рангсиз, ҳар бир парол учун алоҳида. Хеш олишдан олдин
паролга қўшилади. Энди бир хил пароллар турли хеш беради ва тайёр
жадвал беқарор бўлади: ҳар бир парол учун ўзиники керак.

**Секин хешлаш.** Одатий sha256 тезда ишлайди — бу тезлик учун, ҳимоя
учун эмас. Пароллар учун **атайлан секин** функциялар ишлатилади, ва улар
ўн минг марта такрорланади.

Python стандарт кутубхонасида `hashlib.pbkdf2_hmac` бор:

```python
hashlib.pbkdf2_hmac("sha256", password.encode(), salt.encode(), 100000).hex()
```

`bcrypt` ва `argon2` яхшироқ, лекин улар стандарт кутубхонасида йўқ —
ўрнатилади. `pbkdf2_hmac` — ўрнатишсиз ишлайдиган нарса.

## Сен нима қиласан

Сенга `hashes.txt` — «хеш — сўз» жуфтликлари, интернетда йўқ
ишонтирилган сўзлар. Ва `target.txt` — битта хеш.

1. `brute.py` ёз: сўзларни кезиб, мақсад билан мослигини топ, сўзни
   `crack.txt` га ёз.
2. Топилган паролнинг sha256 ининг биринчи 12 белгисини `proof.txt` га ёз.
3. `salted.py` ёз: бир хил парол учун учта хеш кўрсат — тузсиз,
   биринчи туз, иккинчи туз. Улар фарқ қилиши керак.
4. `notes.md` да жавоб бер: **паролни ҳар қаерда танлаш керак бўлса,
   тузнинг нимага кераги бор?**

## Қандай кўринади

```python
import hashlib

def pbkdf2(password, salt):
    return hashlib.pbkdf2_hmac("sha256", password.encode(),
                               salt.encode(), 100000).hex()


print("тузсиз   :", hashlib.sha256(PASSWORD.encode()).hexdigest())
print("туз A    :", pbkdf2(PASSWORD, "sable-4710"))
print("туз B    :", pbkdf2(PASSWORD, "vireo-9931"))
```

Қатор бир хил, хешлар эса фарқ қилади. Айнан шуни қилади туз.

## Аслида нима сақланади

Парол ҳеч қачон сақланмайди. Сақланадиган — **хеш, туз ва параметрлар**,
чунки тузсиз ва параметрсиз хеш текширув учун беқий. Туз сир эмас: у
хеш ёнида туради ва яширилиши шарт эмас. Яширилиши керак бўлгани —
паролнинг ўзи, уни тизимда йўқ.

## Муҳим

Бу ердаги пароллар ишонтирилган ва лаборатория папкасида турибди.
Ҳақиқий пароллар танланмайди — улар ё эслаб қолдирилади, ё янгиланади.
