# Пароли и хеши

## Зачем это знать

Хеш — это **не шифрование**. Шифрование обратимо: есть ключ, есть исходный
текст. Хеш обратим быть не может: из `a94f8f5` не получить `sable`.

Это хорошо и это плохо одновременно. Хорошо — потому что узнать пароль
нельзя. Плохо — потому что **забытый пароль восстановить невозможно
вообще**. Только сбросить.

## Как это ломается

Многие годы пароли хранили так:

```python
hashlib.sha256(password.encode()).hexdigest()
```

И вот что из этого следует.

**Одинаковые пароли дают одинаковые хеши.** Если у двоих людей пароль
`123456`, в файле утечки будет два одинаковых хеша. По самому хешу нельзя
даже сказать, у скольких людей этот пароль.

**Перебор становится разговором с таблицей.** Кто-то заранее посчитал
хеши миллиардов частых паролей — это называется радужная таблица. Дальше
украденный файл ищут не перебором, а **поиском по готовой таблице**:
нашёл совпадение — узнал пароль.

**Скорость не ограничена.** sha256 считается миллиарды раз в секунду.
Ты можешь проверить миллиард вариантов, пока не заметят.

## Что с этим делают

**Соль.** Случайная строка, своя для каждого пароля. Добавляется к
паролю перед хешированием. Теперь два одинаковых пароля дают разные
хеши, и готовая таблица бесполезна: для каждого пароля нужна своя.

**Медленное хеширование.** Обычный sha256 специально быстрый — это нужно
для скорости, а не для защиты. Для паролей используют функции,
которые **намеренно медленные**, и повторяют их десятки тысяч раз.

В стандартной библиотеке Python есть `hashlib.pbkdf2_hmac`:

```python
hashlib.pbkdf2_hmac("sha256", password.encode(), salt.encode(), 100000).hex()
```

`bcrypt` и `argon2` лучше, но их нет в стандартной библиотеке — их ставят
отдельно. `pbkdf2_hmac` — то, что доступно без установки.

## Что ты сделаешь

Тебе дадут `hashes.txt` — пары «хеш — слово», выдуманные слова, которых
нет в интернете. И `target.txt` — один хеш.

1. Напиши `brute.py`: перебери слова, найди совпадение с целью, запиши
   слово в `crack.txt`.
2. Запиши в `proof.txt` первые 12 символов sha256 найденного пароля.
3. Напиши `salted.py`: для одного и того же пароля покажи три хеша —
   без соли, с первой солью, со второй. Они должны различаться.
4. Ответь в `notes.md`: **зачем нужна соль, если пароль всё равно
   приходится перебирать?**

## Как это выглядит

```python
import hashlib

# Здесь -- для примера. Подставь то слово, которое ты нашёл в crack.txt.
PASSWORD = "brindle"


def pbkdf2(password, salt):
    return hashlib.pbkdf2_hmac("sha256", password.encode(),
                               salt.encode(), 100000).hex()


print("без соли  :", hashlib.sha256(PASSWORD.encode()).hexdigest())
print("соль A    :", pbkdf2(PASSWORD, "sable-4710"))
print("соль B    :", pbkdf2(PASSWORD, "vireo-9931"))
```

Строка одна и та же, а хеши разные. Именно это и делает соль.

## Что хранят на самом деле

Никогда не хранят пароль. Хранят **хеш, соль и параметры** — потому что
без соли и параметров хеш бесполезен для проверки. Соль не секрет: она
лежит рядом с хешем и её не надо прятать. Прятать надо само значение
пароля, которого в системе нет.

## Важно

Пароли в задании выдуманы и лежат в твоей лабораторной папке. Реальные
пароли не подбирают — их либо помнят, либо сбрасывают.
