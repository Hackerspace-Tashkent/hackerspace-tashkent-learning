# Shell ижро қиладиган нарсани ишга туширганда

## Нима учун билиш керак

Олдинги мавзуларда зарар SQL ва HTML орқали келган: маълумот сўровга
ёки саҳифага айланган. Бу ерда у ҳаммасигача shell га етади.

Сервер «хост жавоб берадими» деб текширмоқчи. У буйруқ ёзиб ишга
туширади. Агар хост номи сўровдан келиб, сатрга айнан қўйилса,
фойдаланувчи ўз буйруғини қўшиб қўя олади.

Бу **command injection**, буйруқ инъекцияси.

## Қаерда пайдо бўлади

Хавфли қатор оддий кўринади ва шубҳа уйғотмайди:

```python
out = subprocess.run(
    f"ping -c 1 {host}",
    shell=True, capture_output=True, text=True)
```

`host` сўровдан келди. `shell=True` сатрни интерпретаторга беради, у
эса уни бўлакларга ажратади. Хост номидаги `;` бир текширувни икки
буйруққа айланади.

## Нима учун бу камдан-кам ҳолат эмас

«Бу ерда `;` ёки `&&` йўқми» деган текширув ишламайди. Тақиқланган
белгилар рўйхати доим воқеадан қисқа:

- бўлувчилар фақат `;` эмас — `&&`, `||`, қатор охири, `$( )` ҳам;
- бўшлиқ хавфсиз аргументларни ўтказиб юборади;
- тиқиқ ва `$()` `;` сиз ҳам ишлайди;
- URL-кодлаш ва дастур даражасидаги йўллар янги йўллар очади.

## Бунинг ўрнига

**Буйруқ сатри яратманг.** Аргументларни рўйхат қилиб беринг:

```python
out = subprocess.run(["ping", "-c", "1", host],
                     capture_output=True, text=True)
```

Бу ерда `host` — битта аргумент, дастур матни эмас. У ичида
`; cat flag.txt` бўлса ҳам, `ping` шу хост номи билан ишга тушади
ва бошқа ҳеч нарса эмас.

**`shell=False` асосий ҳолат бўлсин.** Аниқ `shell=True` камдан-кам
бўлиши ва «буни shellsiz қандай қилиб бўлмайди?» саволини туғириши
керак.

**Агар shell керак бўлса — оқ рўйхат.** Сатрни ёмон нарсанинг
йўқлиги бўйича эмас, рухsat etилганлар рўйхатида борлиги бўйича
текширинг.

## Сен нимага қиласан

Сервер аввал заиф бўлиб туради. Буйруқ инъекция қиласан, кейин
тешикни ёпасан ва белгиларни текшириш рўйхатдан ёмонроқ эканини
тушунтирасан.

## Чегара

Фақат ўз компьютерингиз, фақат `localhost`, фақат фикстура
файллари.
