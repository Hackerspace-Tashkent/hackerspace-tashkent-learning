# Как браузер исполняет то, что прислал сервер

## Зачем это знать

В предыдущей теме мы доставали данные из чужой таблицы запросом к серверу.
Здесь всё наоборот: мы не отправляем запрос, мы **отправляем код**,
и его исполняет чужой браузер.

Страница считается кодом, а не текстом. Браузер получил строку — и спросил
её у HTML-парсера: это тег? это текст? Если тег — он его строит. Название
такой атаки — **XSS**, cross-site scripting, межсайтовый скриптинг.

## Что делает сервер

Обычная страница отзывов. Человек пишет отзыв, сервер сохраняет и
показывает его **всем**, кто откроет страницу.

Пока отзыв проходит через экранирование, это безопасно: `<` превращается
в `&lt;` и браузер показывает символ, а не строит тег.

```python
import html
safe = html.escape(user_input)   # <  →  &lt;
```

## Где ломается

Любая из этих строк отдаёт пользовательский ввод в HTML без экранирования:

- тело ответа целиком;
- `f"<p>{body}</p>"`;
- вставка в значение атрибута;
- вставка внутрь `<script>`.

Одна такая строка — и любой посетитель страницы выполняет чужой код.
Не администратор, не разработчик: **посетитель**.

## Нагрузка

Классическая нагрузка выглядит так:

`<img src=x onerror=alert(1)>`

Читается так: тег `img` с битым `src` не загрузится, браузер выдаст
ошибку и выполнит `onerror`. Без картинок и без сети.

Текст внутри `alert` не важен. Важен факт: **код исполнился**.

## Что ты сделаешь

Сервер у тебя будет свой. Ты напишешь его так, чтобы уязвимость была,
снимешь её — и объяснишь, чем именно защита отличается.

## Граница

Только свой компьютер, только `localhost`, только синтетические данные
из фикстуры. Никаких чужих сайтов.
