# Запрос, который отправляют не ты

## Зачем это знать

До сих пор вред приходил в запросе: SQL в строке, `<script>` в теле,
`;` в имени хоста. Всё это отправлял **ты сам**.

CSRF устроен наоборот. Вредоносного кода нет вообще. Есть обычная
страница, которая отправляет **обычный** запрос — а браузер сам
добавляет cookie сессии, потому что они положены для этого домена.

Сервер видит: запрос пришёл, cookie пришли, пользователь авторизован.
Действие выполняется.

**CSRF** — cross-site request forgery, подделка запроса с другого сайта.

## Почему cookie так уязвимы

Cookie отправляются **автоматически**. Браузер не спрашивает согласия и
не показывает, куда ушли данные. Это удобство и одновременно источник
проблемы: браузер не может отличить

- запрос, который сделал ты, нажав кнопку;
- запрос, который заставила отправить чужая страница.

Проверка «пользователь авторизован» выполняется и в том, и в другом
случае.

## Как выглядит атака

На чужой странице лежит форма:

```html
<form action="http://127.0.0.1:8111/action" method="post">
  <input type="hidden" name="email" value="attacker@example.com">
</form>
```

Пользователь открывает страницу. Может даже ничего не нажимать — есть
варианты с автоподачей. Форма отправляется, cookie едут вместе с ней,
почта меняется.

Скрытность ничего не даёт: атрибут `hidden` прячет поле на экране, но не
в запросе.

## Что работает

**Токен, который не знает чужая страница.** Сервер кладёт в форму
случайное значение и запоминает его в сессии. Пришёл запрос — сверяем.
Чужая страница не знает значение, поэтому подделать не может.

Свойство называется **double submit** в простом виде и **synchronizer
token** в строгом: токен хранится на сервере.

**Проверка источника.** `Origin` или `Referer` должны совпадать с
ожидаемыми. Помогает, но полагаться только на это не стоит: заголовок
может не прийти.

**Cookie с `SameSite`.** `SameSite=Lax` не отправляет cookie при POST с
чужого сайта. Мощная защита, но слепая зона есть: она не мешает нападению
с того же сайта и не спасает старые браузеры.

**Подтверждение для важных действий.** Смена почты, пароля и платёжных
данных стоит подтвердить заново.

## Что ты сделаешь

Сервер сначала будет без защиты. Ты покажешь, что чужая страница меняет
почту, потом добавишь токен и объяснишь, что именно он останавливает.

## Граница

Только свой компьютер, только `localhost`, синтетические адреса почты.
