# Where to start

A short map: what is here, where to begin, and what you need to know
in advance. Written 1 October 2026.

## What you need to start

**A computer with a browser and internet. That is all.**

No server of your own, no Linux, nothing to install — it all runs in
Codespaces, right in the browser.

## Honestly about time

**We do not know how long this takes.** So we are not writing a number.

A number would be invented: not one person has gone through these
lessons yet, so we have not a single real measurement. As soon as live
runs exist, real estimates will appear here.

What can be said without inventing: **one lesson is one sitting**,
roughly an evening. Not because we measured it, but because each
lesson's volume was aimed at one session. If a lesson does not fit an
evening, the first run will show it and we will split it.

## Three entries, not two levels

The material used to be split into "levels", and that was wrong. The
numbering promised a staircase that is not there: the GitHub lessons do
not require the networking and processes lessons. So there are three
entries, each for its own goal.

### Entry 1. I want to write scripts

If you want to automate routine, mess with the system, understand how
things work inside.

Order:

1. [Terminal](../../tracks/level-0/01-terminal/en.md)
2. [Files and permissions](../../tracks/level-0/02-files-and-permissions/en.md)
3. [Git](../../tracks/level-0/03-git-basics/en.md)
4. [First script](../../tracks/level-0/04-first-script/en.md)
5. [Scripts in bash](../../tracks/level-1/01-bash-scripts/en.md)
6. [Automation and logs](../../tracks/level-1/02-automation-and-logs/en.md)
7. [Processes and services](../../tracks/level-1/03-processes-and-services/en.md)
8. [Networking](../../tracks/level-1/04-networking/en.md)

Needed in advance: nothing.

### Entry 2. I want to work with GitHub and put a site online

If you already have code you want to show, or you want your own site.
Only the most basic terminal is needed.

Order:

1. [Git](../../tracks/level-0/03-git-basics/en.md)
2. [GitHub: fork, pull request, review](../../tracks/level-1/05-github-workflow/en.md)
3. [GitHub Actions](../../tracks/level-1/06-github-actions/en.md)
4. [GitHub Pages](../../tracks/level-1/07-github-pages/en.md)

Needed in advance: being able to open a terminal and use a browser.
The first four lessons are not required.

### Entry 3. I want to understand processes and networking

If you are curious why a program hangs and what a port is.

Order:

1. [Terminal](../../tracks/level-0/01-terminal/en.md)
2. [Processes and services](../../tracks/level-1/03-processes-and-services/en.md)
3. [Networking](../../tracks/level-1/04-networking/en.md)

## How to know you are done

**The lab gives all the ticks — that is a minimum, not the finish.**

One real sign: you can explain what a line you did not write does.
If you can, you understood. If it is simply green but you cannot
explain, you repeated rather than understood.

## What is not here yet

An honest list, so there are no surprises:

- **HTTP API** — promised as a direction, no lesson exists
- **Embedded and hardware** — the equipment plan is written, no lessons
- **MQTT and IoT** — none
- **Level 2** — was promised, not written
- **Time estimates** — will appear after the first live runs

## Where people get stuck

**We do not know.** Not one person has gone through this material.

That is not a weakness and not a hidden flaw — it is what we are
measuring right now. Everyone who gets through the first lesson will
tell us where it was unclear, and we will fix it. So if something is
unclear, that is a finding, not your mistake. Tell us.

## If you would rather do than read

Open the first lesson and run the first command. Everything else only
makes sense after that.
