# Практика S0-02: секрет в коде

| # | Требование | Что это значит |
|---|---|---|
| 1 | в `proof.txt` хеш ключа, найденного в истории | ты действительно искал в истории |
| 2 | в `lab-work/notes.md` есть ответ, а не пустой файл | пустой файл не засчитывается |
| 3 | ты закоммитил свою работу | фикстура оставляет 2 коммита, у тебя будет 3 |
| 4 | в `.gitignore` появилась запись про секреты | не просто файл, а осмысленная запись |
| 5 | история всё ещё хранит ключ — и это правильно | переписывать историю **не надо** |

Пятый пункт выглядит странно, и это главное. Ключ уже убран из файла
во втором коммите — и всё равно лежит в истории. Если ты «починишь» это
переписыванием истории, задача не зачтётся: так в настоящей работе не
делают. Ключ считают сгоревшим и выпускают новый.

**Ни один пункт не засчитывается за то, что сделала фикстура.**
На `setup-repo.sh` приходится ровно ноль из пяти.

## Порядок

1. `bash setup-repo.sh` — создаёт `lab-work/repo` с историей из двух
   коммитов. Ключ есть в первом, во втором его уже нет.
2. Найди ключ в истории командами из урока.
3. Запиши его хеш в `lab-work/proof.txt`.
4. Добавь в `.gitignore` запись про секреты — например, `*.secret` и
   `.env` — и **закоммитируй**. Без коммита пункты 3 и 4 не зачтутся.
5. Ответь в `lab-work/notes.md`: что нужно, чтобы ключ действительно исчез?
