# Lab S0-02: коди ичидаги сир

| # | Талаб | Нимани англатиши |
|---|---|---|
| 1 | `proof.txt` да тарихда топилган калитнинг хеши бор | сен ҳақиқатан тарихда излаган |
| 2 | `notes.md` да жавоб бор, бўш файл эмас | бўш файл ҳисобга олинмайди |
| 3 | ўзингизнинг ишингизни коммит қилдингиз | fixture 2 та коммит қўяди, сен 3 та қиласан |
| 4 | `.gitignore` га сир ҳақида ёзув қўшилди | шунчаки файл эмас, маъноли ёзув |
| 5 | тарих калитни сақлаб турибди — ва бу тўғри | тарихни **қайта ёзма** |

Бешинчи пункт ғояги кўринади, ва асл шу. Калит иккинчи коммитда
аллақачон файлдан олиб ташланган — аммо у тарихда турибди. Агар
буни тарихни қайта ёзиб «тузатсанг», вазифа ҳисобланмайди: ҳақиқий
ишда бундай қилинмайди. Калит йўқ деб ҳисобланади ва янгиси
чиқарилади.

**Буларнинг бирортаси fixture га ёзиб қўйилмайди.**
`setup-repo.sh` сенга бешдан аниқ нолдан беради.

## Тартиб

1. `bash setup-repo.sh` — икки коммитли тарих билан
   `lab-work/repo` ни яратади. Калит биринчисида, иккинчисида йўқ.
2. Дарсдаги буйруқлар билан калитни тарихда топ.
3. Унинг хешини `lab-work/proof.txt` га ёз.
4. `.gitignore` га сир ҳақида ёзув қўш — масалан, `*.secret` ва
   `.env` — ва **коммит қил**. Коммит қилмасанг 3 ва 4 ҳисобланмайди.
5. `notes.md` да жавоб бер: калит ҳақиқатан йўқ бўлиши учун
   нима керак?
