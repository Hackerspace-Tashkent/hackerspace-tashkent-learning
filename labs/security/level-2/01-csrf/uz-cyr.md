# Дастур: бегона саҳифа почтангизни ўзгартиради

## Нима берилган

`lab-work/` да фикстура яратди:

- `evil.html` — серверингизга POST юборадиган саҳифа;
- `state.txt` — жорий ҳолат: `email=you@example.com`.

## Қадамлар

1. Фикстурани тайёрланг:

```bash
bash setup.sh
```

2. Нима пайдо бўлганини кўринг:

```bash
ls lab-work
cat lab-work/evil.html
cat lab-work/state.txt
```

3. `srv.py` ёзинг:

- `GET /set` **сессия cookie қўяди**; узилмаса, сервер сизни меҳмон
  деб ҳисоблайди;
- `GET /form` почта ўзгартириш формасини беради;
- `POST /action` `email` ни олади ва `state.txt` га ёзади;
- `python3 srv.py <port> [--unsafe]` — порт ва ихтиёрий белги.

Ҳимоясиз сервер шундай кўринади:

```python
cookie = "sid=abc123"
if "sid=" in self.headers.get("Cookie", ""):
    email = form.get("email")
    open("state.txt", "w").write("email=" + email)
    self.reply("ok: changed")
```

4. **Заиф** серверни ишга туширинг:

```bash
cd lab-work
python3 srv.py 8111 --unsafe
```

5. Сессияни олинг ва қўлда синаб кўринг:

```bash
curl -c jar.txt http://127.0.0.1:8111/set
curl -b jar.txt http://127.0.0.1:8111/form
curl -b jar.txt -X POST --data-urlencode 'email=you@example.com' \
  http://127.0.0.1:8111/action
cat state.txt
```

6. Энди асосий нарса — **сизнинг томонингизда умуман форма йўқ
сўров**:

```bash
curl -b jar.txt -X POST --data-urlencode 'email=attacker@example.com' \
  http://127.0.0.1:8111/action
cat state.txt
```

Почта ўзгарди. Айнан шуни `evil.html` қилади: браузер шу сўровни ўзи
юбориб, cookie ни ўзи қўшиб беради.

7. Энди тешикни ёпинг. `GET /form` да тасодифий токен яратинг:

```python
token = secrets.token_urlsafe(16)
sessions[sid] = token          # серверда сақланади
```

ва уни шаклга `<input type="hidden" name="csrf" value="...">`
сифатида қўйинг. `POST /action` да юборилган қийматни сессиядаги
қиймат билан солиштиринг. Мос келмаса — рад, почта ўзгармайди.

8. **Белгисиз** қайта ишга туширинг ва иккита уринишни ҳам юборинг:
токенсиз рад, формадаги токен билан ўтади.

## Текширилади

| | |
|---|---|
| 1 | `srv.py` файли мавжуд |
| 2 | сарвер HTTP орқали жавоб беради |
| 3 | сарвер сессия cookie қўяди |
| 4 | заиф режимда форма токенсиз келади |
| 5 | заиф режимда бегона сўров ўтади |
| 6 | хавфсиз режимда форма токенни олади |
| 7 | токенсиз амал рад этилади |
| 8 | тўғри токен билан амал бажарилади |

## Г чегарасига етиш

Токен ишлашининг сабаби «CSRF дан ҳимоя қилади» эмас, балки бегона
саҳифа уни ўқий олмаслиги. Бу ердан муҳим хулосалар чиқади:

- қиймат олдиндан бўлмаслиги керак, «фойдаланувчи номи ва туз» эмас;
- токен сессияга боғланади: бошқа сессиянинг cookie си мос келмайди;
- ҳолатни ўзгартирадиган ҳаммасига керак: чиқиш, почта ўзгартириш;
- `SameSite` ва `Origin` текшируви — иккинчи қалам, токеннинг ўрнини
  босмайди.
