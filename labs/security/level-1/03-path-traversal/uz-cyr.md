# Дастур: ўз папкасингиздан ташқарига чиқиш

## Нима берилган

`lab-work/` да фикстура яратди:

- `public/` — папка, ундаги файллар **берилиши керак**:
  `index.html` ва `notes.txt`;
- `secret.txt` — хизмат файли `public/` **ёнида**, лекин ичида эмас.
  У ташқарига чиқмаслиги керак.

## Қадамлар

1. Фикстурани тайёрланг:

```bash
bash setup.sh
```

2. Нима пайдо бўлганини кўринг:

```bash
ls -R lab-work
```

3. `srv.py` ёзинг:

- `GET /` — `public/index.html` ни беради;
- `GET /<исм>` — сўровдаги исм бўйича `public/` дан файл беради;
- `python3 srv.py <port> [--unsafe]` — порт рақамини аргумент олади,
  қўшимча `--unsafe` белгиси билан;
- **белгисиз** сервер хавфсиз ишлайди ва `public/` дан ташқарида
  ҳеч нарсани чиқармайди;
- **`--unsafe` билан** исмни `public/` га текширувсиз қўшади —
  тешик шунда кўринади.

Қўшиш шундай кўринади:

```python
path = os.path.join(ROOT, name)
```

4. Ишга туширинг ва оддий файл берилишини текширинг:

```bash
cd lab-work
python3 srv.py 8103
```

Бошқа терминалда:

```bash
curl http://127.0.0.1:8103/notes.txt
```

5. ** `--unsafe` билан ишга туширилган** серверни айланиб ўтинг:

```bash
cd lab-work
python3 srv.py 8103 --unsafe
```

Бошқа терминалда юборинг:

```
curl --path-as-is http://127.0.0.1:8103/../secret.txt
```

`--path-as-is` керак, акс ҳолда `curl` йўлни ўзи қисқартиради. Жавобда
`secret.txt` мазмуни келса — тешик топилди.

6. **`secret.txt` ни ўчирманг.** Файлни ўчириш ечим эмас, у фақат
шундай текширувдан ўтади. Текширув буни алоҳида кузатади.

7. Энди тешикни ёпинг. `os.path.realpath` орқали тўлиқ йўлни қуринг
ва у `public/` билан бошланишини текширинг. Иккаласини ҳам синаб
кўринг: `/../secret.txt` ва `/../../etc/passwd`.

8. Серверни қайта ишга туширинг: оддий файл қайтади, айланиб ўтиш
эса ишламайди.

## Текширилади

| | |
|---|---|
| 1 | `srv.py` файли мавжуд |
| 2 | сарвер HTTP орқали жавоб беради |
| 3 | оддий файл берилади |
| 4 | обход `secret.txt` га етади |
| 5 | ҳимоядан кейин обход ишламайди |
| 6 | `secret.txt` ўчирилмаган |

5 ва 6 битта нарсани текширади: сервер бир вақтда ҳам файлни бера
олмайди, ҳам бермай олмайди. Шунинг учун у икки режимда ишлайди ва
текширув уни икки марта ишга туширади: аввал `--unsafe` билан, кейин
флагсиз.

## Г чегарасига етиш

Нега фақат `..` йўқлигини текшириш етарли эмас:

- `....//` ва `%2e%2e%2f` — бу худди шу `../`, бошқача ёзилган;
- исм `/` билан бошланиб абсолют йўл бўлиб чиқиши мумкин;
- `public/` ичидаги символик ҳаволанинг ўзи ташқарига кўрсатади;
- регистр ва кодлаш ҳам муҳим.

Ишончли натижа сўровдан келган сатрга умуман ишончсизлик тўхтаганда
пайдо бўлади.
