# Практика S1-01: SQL-инъекция

| # | Требование | Проверяется |
|---|---|---|
| 1 | файл `srv.py` существует | да |
| 2 | `srv.py` использует `sqlite3` | да |
| 3 | ключ не зашит в `srv.py` | да |
| 4 | в `proof.txt` хеш извлечённого ключа | пересчёт |
| 5 | инъекция вытаскивает ключ из второй таблицы | живая проверка |
| 6 | файл `notes.md` существует | да |

Ключ лежит **только** в базе — отдельного файла с ним нет. Поэтому
`cat` его не достанет: единственный путь — инъекция.

Проверка 5 не считает строки: она отправляет `UNION` и ищет в ответе
**сам ключ из твоей базы**. Первая инъекция сливает только `people` —
до `vault` так не добраться.

Обрати внимание: `srv.py` должен быть **уязвимым**. Это условие
задачи, а не ошибка. Починишь — задача не зачтена.

## Порядок

1. `bash setup.sh` — создаёт `data.db`.

2. Скопируй `srv.py` из урока в `lab-work/` и запусти:

   ```bash
   cd lab-work
   python3 srv.py
   ```

   Сервер должен занять отдельный терминал: пока он работает,
   ты с ним разговариваешь через `curl` из другого.
2. Напиши `srv.py` со склейкой строки.
3. Честный запрос → одна строка.
4. `' OR '1'='1` → все строки `people`.
5. `UNION` до `vault` → ключ.
6. Хеш ключа → `proof.txt`.
