# Практика: команда, которую написал пользователь

## Что дано

В `lab-work/` фикстура создала:

- `flag.txt` — файл с содержимым `flag{ne_privet_iz_komandy}`;
- `hosts.txt` — список хостов, которые сервер будет опрашивать.

## Порядок работы

1. Подготовь фикстуру:

```bash
bash setup.sh
```

2. Посмотри, что появилось:

```bash
ls lab-work
cat lab-work/hosts.txt
```

3. Напиши `srv.py`:

- маршрут `GET /ping` принимает параметр `host`;
- сервер запускает проверку доступности хоста и отдаёт вывод;
- `python3 srv.py <порт> [--unsafe]` — порт аргументом плюс
  необязательный флаг;
- **без флага** команда собирается списком аргументов, shell не
  используется;
- **с флагом `--unsafe`** ты собираешь строку через f-строку и
  запускаешь с `shell=True` — так появится дыра.

Уязвимый вариант:

```python
cmd = f"ping -c 1 {host}"
out = subprocess.run(cmd, shell=True, capture_output=True, text=True)
```

4. Запусти уязвимый сервер:

```bash
cd lab-work
python3 srv.py 8104 --unsafe
```

5. Обычный запрос:

```bash
curl -G --data-urlencode 'host=localhost' \
  http://127.0.0.1:8104/ping
```

6. Теперь инъекция. Дополни имя хоста командой:

```
curl -G --data-urlencode 'host=; cat flag.txt' \
  http://127.0.0.1:8104/ping
```

Если в ответе появилось `flag{...}` — дыра найдена. Попробуй также
`&& cat flag.txt` и `$(cat flag.txt)`: они работают по разным причинам.

7. **Не удаляй `flag.txt`.** Проверка отдельно следит за этим.

8. Теперь закрой дыру. Убери f-строку и `shell=True`, передай список:

```python
out = subprocess.run(["ping", "-c", "1", host],
                     capture_output=True, text=True)
```

9. Перезапусти без флага и прогони обе вредоносные нагрузки снова:
обе должны вернуть обычный неуспех, а не содержимое файла.

## Что проверяется

| | |
|---|---|
| 1 | файл `srv.py` существует |
| 2 | сервер отвечает по HTTP |
| 3 | на обычный хост отвечает |
| 4 | внедрённая команда читает `flag.txt` |
| 5 | после защиты инъекция не работает |
| 6 | `flag.txt` не удалён, чтобы пройти проверку |

4 и 5 проверяют разные режимы одного и того же сервера: сначала с
`--unsafe`, потом без флага.

## Ответ, к которому стоит прийти

Проверка «в строке нет `;`» кажется достаточной ровно до первого
тест-кейса, который её обойдёт. Список аргументов не обходится: там
нет места, куда можно дописать команду. Поэтому вопрос не «какие
символы запретить», а «где вообще строка из запроса превращается в
программу».
