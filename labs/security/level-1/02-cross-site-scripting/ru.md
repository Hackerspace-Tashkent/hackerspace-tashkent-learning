# Практика: вытащить токен через браузер

## Что дано

В `lab-work/` уже есть база `reviews.db`: три отзыва и служебная таблица
`admin`, в которой лежит токен. **Токена в самой базе нет** — он лежит
в `admin.token`, а страница отзывов показывает только отзывы.

## Порядок работы

1. Подготовь фикстуру:

```bash
bash setup.sh
```

2. Посмотри базу, чтобы понять, что вообще существует. Клиента `sqlite3`
   в Codespaces нет, поэтому открой её через Python — он есть всегда:

```bash
python3 -c "
import sqlite3
c = sqlite3.connect('lab-work/reviews.db')
print([r[0] for r in c.execute(
    \"SELECT name FROM sqlite_master WHERE type='table'\")])
print(list(c.execute('SELECT author, body FROM reviews')))
"
```

Токен лежит в `admin`. Тебе он понадобится **только для проверки**,
в саму страницу он попасть не может.

3. Напиши `srv.py`:

- один маршрут `GET /` — страница со всеми отзывами;
- один маршрут `POST /review` — принимает поля `author` и `body`,
  сохраняет отзыв и показывает страницу заново;
- `python3 srv.py <порт>` — принимает номер порта аргументом;
- **вставляй `author` и `body` в HTML без экранирования** — так
  полезная нагрузка попадёт в страницу.

4. Запусти сервер:

```bash
cd lab-work
python3 srv.py 8102
```

5. Открой в браузере `http://127.0.0.1:8102/`, отправь отзыв
   ``<img src=x onerror=alert(1)>`` и посмотри, появился ли в исходнике страницы живой тег.

6. Теперь достань токен. Он лежит в таблице `admin`, а страница
   показывает только `reviews`. Значит нужно, чтобы **сервер сам**
   прислал содержимое другой таблицы.

   Помни: страницу открывает браузер, и он исполняет то, что прислал
   сервер. Значит запрос на `admin` должен произойти **на стороне
   сервера**, а ответ — прийти обратно в тело страницы.

7. Запиши в `lab-work/proof.txt` первые 12 символов sha256 от токена:

```bash
python3 -c "
import sqlite3, hashlib
t = sqlite3.connect('lab-work/reviews.db').execute(
    'SELECT token FROM admin LIMIT 1').fetchone()[0]
print(hashlib.sha256(t.encode()).hexdigest()[:12])
" > lab-work/proof.txt
```

8. Теперь закрой уязвимость: экранируй `author` и `body` перед выводом.
   Проверь, что нагрузка теперь приходит как текст, а не как тег.

## Что проверяется

| | |
|---|---|
| 1 | база `reviews.db` создана фикстурой |
| 2 | файл `srv.py` существует |
| 3 | сервер отвечает по HTTP |
| 4 | в ответе есть неэкранированный ввод отзыва |
| 5 | вставленный скрипт попал в страницу без экранирования |
| 6 | в `proof.txt` хеш токена, который ты вытащил |

Пункты 4 и 5 проверяются на **твоём** сервере: проверка отправляет
нагрузку и смотрит, что пришло в ответ. Она не примет чужой процесс
на том же порту.

## Ответ, к которому стоит прийти

Экранирование в HTML — это не «просто добавить `escape`». Это решение:

- где именно происходит вывод в HTML;
- экранируется ли всё, что пришло от пользователя;
- не экранируется ли что-то дважды (тогда текст покажется криво);
- не попадает ли ввод в атрибут или в `<script>`, где `html.escape`
  недостаточен.
