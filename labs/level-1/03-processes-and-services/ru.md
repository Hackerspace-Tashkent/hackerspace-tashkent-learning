# Урок 7. Процессы и сервисы

Каждая запущенная программа — процесс с номером. Умение их видеть, уводить в фон и вежливо останавливать — разница между рабочей машиной и непонятной.

## Как смотреть процессы

```bash
ps                  # процессы текущего терминала
ps aux               # все процессы всех пользователей
ps -ef               # то же, другой формат
top                  # обновляется live, q — выход
pgrep -f "python"    # найти по имени
```

У каждого процесса есть каталог в `/proc` с тем же номером. Это честный способ увидеть, что программа думает о себе.

## Фон и остановка

```bash
sleep 300 &        # запустить в фоне
jobs                # что запущено из этого терминала
nohup ./long.sh &   # пережить закрытие терминала
disown -a           # забыть о фоновых процессах

kill 12345          # попросить завершиться (SIGTERM)
kill -9 12345       # убить немедленно (SIGKILL)
```

> **Заметка.** `kill` без заглавной K — не шутка: обычный `kill` вежливо просит. `-9` не перехватывается, и программа не успевает прибраться. Сначала пробуй вежливо.

## Перехват сигнала

`trap` позволяет скрипту выполнить свою уборку при остановке. Без него полузаписанный файл так и останется полузаписанным.

```bash
#!/usr/bin/env bash
tmp="work.tmp"

cleanup() {
  echo "cleaning up..."
  rm -f "$tmp"
}
trap cleanup EXIT TERM

echo "working" > "$tmp"
sleep 30
```

> **Заметка.** Ловушка, которая только пишет в лог и возвращается, недостаточна: цикл продолжает крутиться, и процесс не завершается. Запиши и сделай `exit 0` внутри обработчика. И помни: bash выполняет trap только после того, как доработает текущая команда, — скрипт внутри `sleep 300` проигнорирует твой `kill` на добрые пять минут. Поэтому в практике используются короткие паузы.

## Сервисы и systemd

На настоящей Linux-машине `systemd` запускает программы при загрузке, перезапускает их после падения и собирает их вывод. Сервис описывается файлом юнита.

```ini
[Unit]
Description=My report service
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/report.sh
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Загрузить — `systemctl daemon-reload`, запустить — `systemctl start report`, смотреть — `journalctl -u report -f`.

> **Заметка.** Codespace — контейнер, там `systemd` не является PID 1 и `systemctl status` не работает. Поэтому практика проверяет, что файл юнита написан верно, а не что сервис запущен. На реальной машине ты запустишь его сам.
