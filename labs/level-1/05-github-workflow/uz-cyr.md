# Лаборатория: иш билан GitHub

## Нима қилиш керак

Ҳамма нарса шу файл ёнидаги `lab-work/` папкасида бўлади. Папка дастлаб
йўқ — уни ўзингиз яратинг.

```bash
cd "$(dirname check.sh)"
mkdir lab-work
cd lab-work
```

### 1. Сизнинг форкингиз

Ўқув репозиторийни форк қилинг ва **ўз форкингизни** клонланг, асл нусхани эмас:

```bash
git clone https://github.com/<сизнинг-логин>/hackerspace-tashkent-learning.git
cd hackerspace-tashkent-learning
git remote -v
```

`git remote -v` да `origin` сизнинг логинингизни кўрсатиши керак.

### 2. `main` бўлмаган тармоқ

```bash
git switch -c my-first-change
```

Фақат унинг ичида ишланг. `main` га тегманг.

### 3. Ўзгариш ва коммит

Ҳар қандай файл қўшинг ёки мавжудини ўзгартиринг, кейин:

```bash
git add .
git commit -m "Add my note about level 1"
```

### 4. Pull request таъсифи

`PR.md` яратинг — PR таъсиф майдонига ёзадиган нарса. Камда уч қатор:

```markdown
## Нима ўзгартирилди

## Қандай текширилади

## Мен ўзим нимани текширдим
```

Учинчи сарлавҳа энг қимматли. Ҳалол ёзинг: нимани ишга туширдингиз ва
ҳақиқатан нима ишлайди.

### 5. Рўйхат

`CHECKLIST.md` яратинг, нимани текширганингизни белгиланг. Камда:

```markdown
- [ ] check.sh ўтади
- [ ] ҳар бир скрипт нима қилишини ўқидим
```

### 6. Pull request

Тармоқни пуш қилинг ва PR очинг:

```bash
git push -u origin my-first-change
```

Кейин браузерда ёки, агар `gh` ўрнатилган бўлса:

```bash
gh pr create --fill
```

`gh` йўқ бўлса сайтни очинг, GitHub ўзи PR яратишни таклиф қилади.

## Текширув

```bash
./check.sh
```

Бута маҳаллий текширув ва, агар `gh` бўлса, ўнинчи онлайн текширув.
`gh` йўқ бўлса ҳисоб `9/9` бўлади: бу нормал, маҳаллий қисм ҳисобга олинган.

## Бу лаборатория нимани текширмайди

У сизнинг PR-ингиз маъноси бор ёки йўқлигини текширмайди. Уни одам ўқийди.
Шунинг учун `PR.md` даги учинчи сарлавҳа қолганларидан муҳимроқ.
