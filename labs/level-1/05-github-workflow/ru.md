# Практика: работа с GitHub

## Что делать

Всё происходит в папке `lab-work/` рядом с этим файлом. Папки изначально нет —
создай её сам.

```bash
cd "$(dirname check.sh)"
mkdir lab-work
cd lab-work
```

### 1. Свой форк

Сделай форк учебного репозитория себе и склонируй **свой** форк, а не оригинал:

```bash
git clone https://github.com/<твой-логин>/hackerspace-tashkent-learning.git
cd hackerspace-tashkent-learning
git remote -v
```

В `git remote -v` должен быть `origin` с твоим логином.

### 2. Ветка не в `main`

```bash
git switch -c my-first-change
```

Дальше работаем только в ней. `main` не трогаем.

### 3. Изменение и коммит

Добавь любой файл или измени существующий, затем:

```bash
git add .
git commit -m "Add my note about level 1"
```

### 4. Описание pull request

Создай `PR.md` — то, что ты напишешь в поле описания PR. Минимум три строки:

```markdown
## Что изменено

## Как проверить

## Что я проверил сам
```

Третий заголовок — самое ценное. Пиши честно: что ты запускал и что
действительно получилось.

### 5. Чек-лист

Создай `CHECKLIST.md`, где отметил, что проверено. Хотя бы так:

```markdown
- [ ] check.sh проходит
- [ ] прочитал, что делает каждый скрипт
```

### 6. Pull request

Запушь ветку и открой PR:

```bash
git push -u origin my-first-change
```

Дальше либо в браузере, либо, если установлен `gh`:

```bash
gh pr create --fill
```

Если `gh` нет — открой сайт, GitHub сам предложит создать PR.

## Проверка

```bash
./check.sh
```

Девять локальных проверок плюс, если есть `gh`, — десятая, онлайновая.
Без `gh` счёт будет `9/9`: это нормально, локальная часть уже засчитана.

## Чего эта практика не проверяет

Она не проверяет, что твой PR осмысленный. Его читает человек. Поэтому
третий заголовок в `PR.md` важнее остальных.
