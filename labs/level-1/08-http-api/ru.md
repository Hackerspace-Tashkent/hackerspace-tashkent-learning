# Практика 08: свой HTTP-сервер

## Что сделать

Написать небольшой API, который отдаёт показания датчика воздуха.

| # | Требование | Проверка |
|---|---|---|
| 1 | файл `lab-work/api.py` существует | да |
| 2 | используется `http.server` | да |
| 3 | определён обработчик запросов | да |
| 4 | есть обработчик `GET` | да |
| 5 | данные читаются из файла | да |
| 6 | задан тип содержимого `application/json` | да |
| 7 | есть путь `/health` | да |
| 8 | неизвестные пути дают `404` | да |
| 9 | сервер слушает `127.0.0.1` | да |
| 10 | файл `lab-work/NOTES.md` существует | да |
| 11 | сервер **действительно** отвечает на `/health` | живая проверка |

Одиннадцатая — не чтение файла, а настоящий запуск: проверка поднимает твой
сервер и спрашивает его клиентом. Если не отвечает — покажет вывод
сервера, где будет причина.

## Порядок

1. Скопируй код из урока в `lab-work/api.py`.
2. Создай `lab-work/data.json` с примерами показаний.
3. Запусти `python3 api.py` в отдельном терминале.
4. Проверь `curl` по всем трём путям.
5. В `NOTES.md` ответь письменно:

**Почему в примере `/health` стоит перед `/readings`?**

Подсказка: подумай, что будет, если поменять их местами.

## Проверка

```bash
./check.sh
```
